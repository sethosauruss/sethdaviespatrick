Cybersecurity Home Lab

In progress Rack rebuild planned for December

A self-built home lab simulating a small-scale enterprise IT environment, focused on infrastructure security, system administration and defensive cybersecurity.

View on GitHub

Where it is now

Raspberry Pi 5
A 4GB Pi running CasaOS with Plex and a remote monitoring app for my 3D printer. I've backed up the Plex config and plan to wipe it and rebuild on Raspberry Pi OS Lite with Docker Compose. Everything it runs will then be defined in one file, which is easier to rebuild and document.
pfSense test
I tore down a Fujitsu TeamPoS 7000 (Celeron G540, 4GB) and installed pfSense CE 2.7.2 on it. It booted and worked, with one onboard network port plus a USB gigabit adapter. I'm not using it in the rack because it is too wide for a 10 inch rack and likely draws more power than a small PC would for the same job.
Surface Pro
My first Proxmox host, a repurposed Surface Pro with a broken screen. It's retired now, but the SSH hardening, Fail2Ban, Docker and log analysis work from it is still documented on GitHub.

The December rebuild

The plan is to move to a single rack with a dedicated firewall and network segmentation. Everything has to fit inside it.

Rack
Tecmojo 6U, 10 inch wide and 200mm deep, with a shelf.
Firewall
An HP EliteDesk 800 G3 Mini (i5-7500T) running pfSense, using the USB gigabit adapter I already own as its second port.
Lab host
A second EliteDesk 800 G3 Mini running Proxmox. It starts at 8GB of RAM and goes to 16GB later. It will run Kali Linux, Metasploitable2 and DVWA as practice targets, CALDERA and Atomic Red Team for adversary emulation, MITRE ATT&CK Navigator, and Plex using the CPU's Quick Sync for transcoding.
Switch and console
A TP-Link TL-SG108E managed switch for the VLANs, and a JetKVM for remote console access, moved between machines by hand.
Raspberry Pi 5
Stays as the always-on box. After the rebuild it runs Plex, Pi-hole, Uptime Kuma, the printer monitoring app and Tailscale for remote access.

Network segmentation

  • Lab: the Proxmox host and its practice targets, kept away from everything else.
  • Trusted: everyday devices.
  • IoT: smart and low-trust devices.

Open decisions

  • Wazuh or a self-built ELK stack. The SIEM is put off until the lab host has 16GB, because it shares that machine with Kali, the practice targets and the emulation tools.

Cut from the build: UPS, patch panel, a second Pi, a KVM switch, Jellyfin and the Minecraft Bedrock server.

Documentation

Everything is documented on GitHub. I plan to film the rack assembly and cabling and add short videos here once the build is done.
